## 核心洞察

### Warp 开源宣布

> **今天我们宣布构建 Warp 方式的根本变化：Warp 客户端现在开源，社区可以使用由 Oz 管理的 Agent 优先工作流参与构建。**

**Oz**: Warp 的云 Agent 编排平台。

**赞助**: OpenAI 是新开源项目的创始赞助商，新 Agent 管理工作流由 OpenAI 模型驱动。

---

### 为什么开源？两大原因

#### 原因 1: 构建更好的 Warp，更快

> **我们认为如果开源并与社区合作帮助监督 Agent 舰队，可以更快交付更好的 Warp。**

**开发瓶颈已转移**:
```
过去：写代码是瓶颈
现在：代码生成不是瓶颈
瓶颈：人类在环活动
- 规范产品
- 验证行为
- 内部团队能力和节奏有限
```

**Agent 处理繁重工作**:
- 编码
- 规划
- 测试
- 实施

**人类聚焦高杠杆工作**:
- 塑造构建什么
- 确保构建正确

---

#### 原因 2: 给开发者塑造未来的机会

> **市场上没有完整功能的开源 Agent 开发环境，我们想给社区提供封闭源选项的替代方案。**

**没有人确切知道 Agent 开发未来看起来像什么，我们认为社区应该能够参与塑造它。**

**Warp 是多模型多 harness 的**，想加倍这种开放性。开放将允许更响应用户，与他们合作处理长尾 backlog，让 Warp 成为市场上最佳 ADE（Agent 开发环境）。

---

### 三个产品改进

#### 1. 更广泛开源模型支持

**新模型**:
- Kimi
- MiniMax
- Qwen

**新功能**: "auto (open)" 模型路由版本，自动为任务选择最佳开源模型。

---

#### 2. 自定义 Warp 体验

**三个层次**:
| 层次 | 功能 |
|------|------|
| **基础** | 仅终端 |
| **中间** | 最小功能（diff 视图 + 文件树）改善 Agent 开发 |
| **完整** | 全功能 ADE，内置 Agent |

---

#### 3. 设置文件（长期缺失）

**功能**:
- 用户和 Agent 可编程控制设置
- 设备间轻松移植
- 长期缺失功能终于交付

---

### 开源细节

**许可证**: AGPL  
**仓库**: GitHub 可用  
**贡献流程**: Agent 做繁重工作（编码/规划/测试），社区成员帮助想法/方向/验证。

**Warp 团队角色**: 帮助指导构建什么、何时、如何，但认为 Warp 根本上成为与社区协作努力。

**机会**: 为近百万活跃开发者使用快速增长应用做贡献，与 Warp 团队紧密合作。

---

### Agent 工作流架构

**模型**: OpenAI 模型驱动  
**平台**: Oz（Warp 云 Agent 编排平台）  
**偏好**: 用 Oz 因为内置正确技能和验证循环

> **OpenAI 支持**: "开源长期是开发者学习/构建/推动领域前进核心。我们兴奋支持探索 AI 如何帮助维护者和贡献者更有效地规模化协作的实验。" — Thibault Sottiaux, OpenAI 工程主管

---

### 从封闭到开放产品开发

**转变**:
- 封闭产品开发 → 开放产品开发
- 公开 GitHub issues 成为追踪功能真相源
- 公开 ADE 路线图
- 公开 ADE 问题技术和产品讨论

---

### 商业逻辑

> **开源根本上来自我们构建成功商业渴望。**

**竞争现实**:
- 与高度资助封闭源竞争对手竞争
- 没有资源竞争价格或大规模补贴使用
- 需要通过向最兴奋社区提供最佳产品构建业务

**社区价值**:
- 社区塑造未来有内在价值
- Warp 有 5 年工程独特产品
- 希望为社区提供构建 Agent 开发未来令人信服的起点
- 超越任何其他开源替代方案

---

### 五年愿景回顾

**5 年前启动 Warp 作为终端时，计划总是开源客户端。**

> **我们每年辩论是否开源，今年第一次因为 Agent 兴起平衡转移。我做开发者很长时间，从未见过像现在发生这样变化。**

**Warp 使命**: 赋能开发者更快交付更好软件。希望通过改变构建方式更接近实现那使命。
