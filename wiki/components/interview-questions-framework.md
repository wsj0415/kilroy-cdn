# 采访式提问框架

**用途**: 内容创作前澄清需求，避免通用输出  
**问题数**: 6-10 个（根据任务复杂度调整）  
**来源**: Sharbel 12 Claude 用法 + Kilroy 内容创作实践

---

## 核心问题列表

### 必问（6 个）

1. **目标受众是谁？**
   - 技术背景还是非技术？
   - 年龄段/职业/痛点？
   - 他们已经在用什么解决方案？

2. **核心信息是什么？**
   - 用一句话说清楚你要表达什么
   - 读者读完应该记住的一个点

3. **发布平台？**
   - 微头条 / 小红书 / B 站 / 公众号 / 抖音
   - 不同平台格式差异巨大

4. **语气风格？**
   - 专业严肃 / 轻松幽默 / 犀利吐槽 / 温暖共情
   - 有没有参考的账号/文章？

5. **关键包含点？**
   - 必须提到的数据/案例/人名
   - 必须引用的来源

6. **关键排除点？**
   - 绝对不能提的
   - 敏感话题/竞品/争议

---

### 选问（根据任务加 2-4 个）

7. **长度要求？**
   - 微头条 300-500 字
   - 小红书 800-1200 字
   - B 站 1500+ 字
   - 还是随便？

8. **行动号召？**
   - 引导关注/评论/私信
   - 引流到私域/产品页
   - 纯分享不转化？

9. **发布时间？**
   - 影响时效性内容
   - 影响热点关联

10. **有参考样本吗？**
    - "类似 XX 那篇的风格"
    - 直接给链接最高效

---

## 使用方式

### 完整模式（新任务/重要内容）
```
问全部 6 个必问 + 2-4 个选问
适用于：重要内容、新类型、第一次合作
```

### 快速模式（常规任务）
```
只问 3 个核心：
1. 目标受众
2. 核心信息
3. 发布平台
适用于：日常内容、系列连载
```

### 极简模式（紧急/熟悉需求）
```
只问 1 个：
"这次有什么特别要注意的？"
适用于：紧急发布、老手合作
```

## 实际案例

### 案例 1：Karpathy LLM Wiki 分析改编

**任务**: 将 Karpathy LLM Wiki 分析改编为微头条

**采访记录**:
1. 受众：AI 从业者 + 技术管理者（25-40 岁）
2. 核心信息：LLM Wiki 解决上下文失忆，让 AI 真正记住项目
3. 平台：微头条
4. 语气：专业但易懂，带点兴奋感
5. 包含点：5000+ stars、raw/wiki 架构、复合效应
6. 排除点：不 technical 细节、不比较竞品
7. 长度：300-500 字
8. CTA：引导评论"想要 schema 模板"

**输出**: 3 版微头条文案，选 1 版发布

---

### 案例 2：小红书封面图提示词

**任务**: 为 LLM Wiki 内容生成封面图提示词

**采访记录**:
1. 受众：小红书创作者（20-35 岁女性为主）
2. 核心信息：LLM Wiki=第二大脑，AI 帮你记笔记
3. 平台：小红书（3:4 竖版）
4. 语气：温暖、专业、有设计感
5. 包含点：Bento Grid 风格、数据可视化
6. 排除点：不要太技术、不要代码元素
7. 长度：提示词本身
8. 参考：[链接到喜欢的笔记]

**输出**: 3 版封面图提示词，带示例图链接

## 归档规则

- 每次采访记录保存到 `wiki/decisions/content-brief-XXX.md`
- 链接到相关的 wiki 概念页面
- 累积成"用户偏好知识库"
- 下次类似任务可以直接参考
