## 摘要

LLM Wiki 是 Karpathy 提出的个人知识库模式 — LLM 不再只是检索原始文档（如 RAG），而是增量构建并维护一个持久的 Wiki（结构化 Markdown 文件集合）。知识被编译一次并保持更新，而非每次查询时重新推导，实现知识的持续复合积累。核心架构：raw/（不可变来源）→ wiki/（LLM 维护）→ schema.md（行为宪法）。

---

## 核心理念

### 问题：RAG 的局限

大多数人与 LLM 和文档的体验是 RAG 模式：
- 上传一批文件
- LLM 在查询时检索相关片段
- 生成答案

**问题**: LLM 每次都在从头重新发现知识。没有积累。问一个需要综合五份文档的微妙问题，LLM 必须每次都找到并拼凑相关片段。

### 解决方案：LLM Wiki

LLM **增量构建并维护一个持久的 Wiki**：
- 结构化、相互链接的 Markdown 文件集合
- 位于你和原始来源之间
- 添加新来源时，LLM 阅读、提取、整合到现有 Wiki
- 更新实体页面、修订主题摘要、标记矛盾

**关键区别**: 知识被编译一次，然后保持更新，而不是每次查询时重新推导。

## 三层架构

### 1. Raw Sources（原始来源）
- **位置**: `raw/` 文件夹
- **内容**: 文章、论文、图像、数据文件
- **特性**: **不可变的** — LLM 从它们阅读但从不修改
- **用途**: 真相源

### 2. The Wiki（编译知识）
- **位置**: `wiki/` 文件夹
- **内容**: 摘要、实体页面、概念页面、比较、概述
- **特性**: **LLM 完全拥有** — 创建、更新、维护交叉引用
- **原则**: 你阅读它；LLM 编写它

### 3. The Schema（行为宪法）
- **位置**: `schema.md`
- **内容**: Wiki 结构、约定、工作流
- **特性**: **关键配置文件** — 使 LLM 成为纪律严明的 Wiki 维护者
- **演化**: 你和 LLM 共同演化

---

## 三操作

### Ingest（摄入）
```
1. 将新来源放入 raw/
2. LLM 阅读来源，讨论关键要点
3. 在 wiki/ 中写摘要页面
4. 更新 index.md
5. 更新相关实体和概念页面
6. 追加条目到 log.md
```

**单个来源可能触及 10-15 个 wiki 页面。**

### Query（查询）
```
1. 对 wiki/ 提问
2. LLM 搜索相关页面，阅读它们
3. 综合带引用的答案
4. 答案可以是：Markdown 页面、比较表、幻灯片、图表

**重要洞察**: 好的答案可以作为新页面归档回 wiki/。
```

### Lint（健康检查）
```
频率：每周日

检查项:
- 页面间的矛盾
- 被新来源取代的旧声明
- 无入链的孤立页面
- 被提及但缺少自己页面的重要概念
- 缺失的交叉引用
- 可通过网络搜索填充的数据空白
```

---

## 两特殊文件

### index.md（内容目录）
- **用途**: Wiki 中一切的目录
- **格式**: 每个页面列出带链接、一行摘要、可选元数据
- **组织**: 按类别（实体、概念、来源等）
- **更新**: LLM 在每次摄入时更新
- **规模**: 在中等规模（~100 来源、~数百页面）下效果出奇好

### log.md（时间日志）
- **用途**: 追加式的记录 — 发生了什么、何时发生
- **格式**: `## [2026-04-02] ingest | 文章标题`
- **解析**: 可用简单 unix 工具 — `grep "^\[\[" log.md | tail -5`
- **价值**: 给你 Wiki 演变的时间线

## 为什么这有效

### 人类 vs LLM 分工

| 人类的工作 | LLM 的工作 |
|-----------|-----------|
| 策划来源 | 总结 |
| 指导分析 | 交叉引用 |
| 问好问题 | 归档 |
| 思考意味着什么 | 记账 |

**关键洞察**: 维护知识库的枯燥部分不是阅读或思考 — 而是记账。LLM 不无聊、不忘更新交叉引用、可以一次触及 15 个文件。

### 与 Memex 的关系

这个想法精神上相关于 Vannevar Bush 的 [Memex (1945)](https://en.wikipedia.org/wiki/Memex)：
- 个人策划的知识存储
- 文档间有关联轨迹
- 私人的、积极策划的
- 连接与文档本身一样有价值

**Bush 无法解决的部分**: 谁做维护。**LLM 处理那个。**

## 实施案例

### WorldofAI 前端+CRM 项目

**输入**:
- React/TypeScript 代码库
- Shadcn/ui 组件
- CRM 需求
- API 规范
- 过去的决策

**输出**:
- 发现并记录所有现有 Shadcn 组件
- 为数据模型、用户流和架构决策创建相互链接的页面
- 请求仪表板时，参考 wiki 获取现有模式
- 选择合适的 Shadcn 包，确保一致性
- 用新实现细节更新 wiki

**效果**: 感觉像与一位资深工程师合作，他深刻内化了整个项目并积极演化其理解。
